# `create-epbaby-pixel-pet` 使用手册

本手册面向 epBaby 项目成员，说明如何调用项目专用 skill 创建像素宠物。执行规则以同目录下的 `SKILL.md` 为准，中文规则译本见 `SKILL.zh-CN.md`。

## 1. 使用条件

该 skill 仅在 epBaby 仓库内使用：

```text
D:\code\project\epBaby
```

开始前应准备：

1. 至少一张清晰的角色参考图；正面、侧面或武器细节图越完整，角色一致性越好。
2. 所需动作列表，以及每个动作的运动过程说明。
3. 角色不得改变的身份特征，例如发型、服装、武器数量、惯用手、颜色和配饰。
4. 如果是修改已有宠物，提供现有宠物 ID 和需要保留的动作。

不需要把 skill 安装到全局目录。只要 Codex 当前工作区是 epBaby，它就能发现项目内的 skill。

## 2. 如何调用

最稳妥的方式是在请求中显式写出 skill 名称：

```text
使用 $create-epbaby-pixel-pet 创建一个新的像素宠物。
```

随后附上角色参考图、动作说明和身份约束。也可以直接把图片附加到对话中，并在文字中说明每张图片的用途。

## 3. 推荐的请求模板

复制下面的模板并替换内容：

```text
使用 $create-epbaby-pixel-pet 创建并接入一个新的 epBaby 像素宠物。

角色名称：<角色名称>
建议宠物 ID：<lowercase-kebab-case，可留空让 Codex 生成>

角色参考图：
- <附件或项目内图片路径>
- <可选的服装、武器、侧面参考图>

身份特征，任何帧都不能改变：
- <发型和发色>
- <服装和主色>
- <武器、道具及其数量>
- <惯用手、伤疤、饰品等关键特征>

需要的动作：
1. <动作名称>：<从开始到结束的运动过程；是否循环>
2. <动作名称>：<动作过程；是否循环>
3. <动作名称>：<动作过程；是否循环>

其他要求：
- <是否需要桌面窗口跟随移动>
- <动作速度或情绪>
- <必须保留或禁止出现的特效>

执行要求：
- 先生成并检查所有动作精灵图。
- 每个动作从 8 帧开始，不够流畅则升级到 16 帧、32 帧。
- 精灵图通过后，参考 reference/Beads_demo 逐帧生成拼豆图纸。
- 使用统一锚点和紧凑画布，避免顶部与四周浪费空间。
- 最终宠物必须只根据批准的拼豆图纸生成，并达到逐格、逐色、逐帧零差异。
```

## 4. 完整示例

```text
使用 $create-epbaby-pixel-pet 创建并接入一个新的 epBaby 像素宠物。

角色名称：红围巾机械狐狸
建议宠物 ID：scarf-mecha-fox

角色参考图：
- D:\code\project\epBaby\reference\scarf-mecha-fox\front.png
- D:\code\project\epBaby\reference\scarf-mecha-fox\weapon.png

身份特征，任何帧都不能改变：
- 银灰色机械狐狸，右耳缺角，左眼为青色发光义眼。
- 始终佩戴红色长围巾，围巾末端有两个黑色缺口。
- 右前爪装备单把短刃，不能换手，也不能增加第二把刀。
- 身体比例、耳朵大小和尾巴数量在所有动作中保持一致。

需要的动作：
1. idle：原地待机呼吸，尾巴轻摆，循环动作。
2. walk：向右行走，四肢步态完整，循环动作，并让桌面窗口水平移动。
3. slash：先收刀蓄力，再向前斩击，围巾和刀光随动作延迟摆动，非循环动作。
4. sleep：趴下入睡，呼吸灯缓慢闪烁，循环动作。

执行要求：
- 每个动作先测试 8 帧；不流畅则依次升级到 16 帧和 32 帧。
- 画布应根据全部动作的联合边界紧凑裁切，人物顶部目标留白为 2 像素。
- 每张拼豆图纸只能包含当前一帧，不能混入相邻帧的刀光、围巾或身体部件。
- 最终项目与拼豆图纸必须零像素差异。
```

## 5. 执行过程与验收节点

### 阶段一：动作精灵图

Codex 会为每个动作先制作 8 帧精灵序列并生成播放预览，检查：

- 角色身份和比例是否稳定；
- 动作轨迹是否连续；
- 武器、衣服、头发和特效是否合理跟随；
- 循环动作首尾是否无跳变；
- 是否存在复制帧造成的停顿。

8 帧不通过时会重新制作 16 帧；16 帧仍不通过时会制作 32 帧。不同动作可以使用不同帧数。

建议在这一阶段确认：

```text
阶段一通过，可以继续生成拼豆图纸。
```

如果需要调整，可以直接指出动作和问题：

```text
walk 的第 6 到第 8 帧重心跳动明显，请升级到 16 帧重新生成。
slash 的刀必须始终在右手，刀光出现时间再延后两帧。
```

### 阶段二：拼豆图纸

动作通过后，Codex 会为每一帧单独生成一张拼豆图纸。图纸应包含坐标、网格、色号和每种颜色的准确数量。

这一阶段重点确认：

- 每张图纸只有一个动作帧；
- 所有帧人物坐标、锚点和地面线固定；
- 顶部和四周没有明显无效空白；
- 32、64、128、192 仅作为细节档位上限，不强制使用正方形画布；
- 精灵帧与拼豆图纸的有色像素数量、色号数量和坐标完全一致；
- 图纸重建结果与精灵帧逐像素差异为零。

建议在这一阶段确认：

```text
阶段二图纸通过，可以根据图纸生成最终宠物。
```

发现问题时可这样反馈：

```text
图纸顶部空白仍然过多，请按全部帧的联合边界重新计算画布。
slash 第 4 帧混入了第 5 帧的刀光，请清空缓冲区并重新生成该动作全部图纸。
```

### 阶段三：最终像素宠物

Codex 只能从已批准的拼豆图纸解析最终宠物，不能重新参考原角色图进行近似绘制。

最终应交付：

- `default-pets/<pet-id>.json`；
- `scripts/generate-<pet-id>.mjs`；
- 每个动作的独立精灵帧和动画预览；
- 每一帧对应的拼豆图纸；
- 画布、联合边界、枢轴点、地面线和留白数据；
- 精灵图到图纸、图纸到项目的零差异报告；
- 默认宠物迁移位置；
- 项目验证和生产构建结果。

## 6. 建议的素材与产物目录

以下是推荐结构；生成器和默认宠物文件的位置属于强制约定，其余目录可以根据现有项目组织调整：

```text
reference/
└─ <pet-id>/
   ├─ source/                 角色参考图
   ├─ sprites/
   │  ├─ <action-id>/        每个动作的独立帧
   │  └─ previews/           GIF、APNG 或总览预览
   ├─ charts/
   │  └─ <action-id>/        一帧一张拼豆图纸
   └─ validation/            像素差异与色号统计报告

scripts/
└─ generate-<pet-id>.mjs

default-pets/
└─ <pet-id>.json
```

## 7. 如何判断任务真正完成

只有下列项目全部满足时才算完成：

- 所有动作都有明确说明并已生成；
- 每个动作采用通过流畅度检查的最小帧数档位；
- 每个精灵帧都有且只有一张对应拼豆图纸；
- 所有图纸使用统一人物位置和紧凑画布；
- 没有任何相邻帧内容污染；
- 精灵图到图纸的逐像素差异为零；
- 图纸到最终项目的逐像素差异为零；
- 每种色号的数量完全一致；
- 项目 JSON 通过验证；
- `npm.cmd run build` 成功；
- 构建目录中的宠物 JSON 与源文件一致。

“看起来很像”不能代替零差异验证。

## 8. 修改已有宠物

修改已有宠物时仍使用同一个 skill，并明确宠物 ID、需要修改的动作和必须保留的内容：

```text
使用 $create-epbaby-pixel-pet 修订现有宠物 moss-jester-cat。

只修改 umbrella 动作：当前 8 帧播放时雨伞和手腕有跳变，请升级到 16 帧。
保持其他动作、角色外观、色板和项目 ID 不变。
重新生成 umbrella 的全部精灵帧与拼豆图纸，并增加新的默认迁移版本。
```

修订已发布的默认宠物时，不能修改旧迁移 ID，必须增加新的版本号，例如从 `default-<pet-id>-v1` 增加为 `default-<pet-id>-v2`。

## 9. 什么时候使用 `import-pixel-pet`

下面情况使用 `$import-pixel-pet`，不需要运行完整创建流程：

- 已经有审核通过的索引精灵帧或拼豆图纸，只需要转换为 `EditorProject`；
- 只需要修复现有生成器或 JSON；
- 只需要把已有宠物接入默认库；
- 不需要重新设计动作、检查 8/16/32 帧或生成新图纸。

如果任务包含“从角色参考图设计动作”，应使用 `$create-epbaby-pixel-pet`。

## 10. 常见问题

### 可以强制只做 8 帧吗？

可以把 8 帧作为目标，但如果播放检查不流畅，skill 会按规则升级到 16 或 32 帧。不能为了固定 8 帧而接受明显卡顿。

### 所有动作必须使用相同帧数吗？

不需要。待机可以是 8 帧，复杂攻击可以是 16 或 32 帧。生成器必须分别断言每个动作的实际帧数。

### 所有图纸必须是 64×64 或 128×128 吗？

不需要。64 和 128 是细节档位的最长边上限。最终画布应根据所有帧的联合边界生成，可以是 52×61、84×72 等紧凑的非正方形尺寸。

### 为什么人物不能在每帧单独居中？

逐帧居中会导致播放时人物抖动。所有帧必须共用枢轴点、地面线和坐标，画布紧凑化应基于全部帧对齐后的联合边界。

### 如何保证最终宠物 100% 按图纸还原？

最终宠物只从已批准图纸解析。每帧都会重新渲染为索引像素，与图纸逐格比较，并核对每种色号数量。坐标、色号、透明度、尺寸或帧顺序存在任何差异都不能通过验收。
