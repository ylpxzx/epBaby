# 创建 epBaby 像素宠物

> 本文件是供团队成员阅读的中文译本，不参与 Codex skill 的识别或执行。实际执行规范以同目录下的 `SKILL.md` 为唯一准则。

通过三个分别验收的阶段创建宠物：先生成动作精灵图，再生成拼豆图纸，最后生成可编辑的像素宠物。整个过程必须保持角色身份一致、动作连续、帧内容彼此隔离、布局紧凑，并严格忠于最终图纸。

## 限定使用范围

1. 确认工作区包含 `src/shared/editor-project.ts`、`src/main/editor-project-store.ts`、`default-pets/` 和 `reference/Beads_demo/`。
2. 如果缺少上述路径，立即停止。该流程只能用于 epBaby 项目。
3. 除非用户明确要求替换或删除，否则保留所有现有宠物。
4. 除非用户明确要求，否则不要启动 Electron。默认应完成生成、预览、验证、类型检查和构建。
5. 在修改存储、初始化数据、渲染或包脚本前，阅读 [epBaby 项目契约](../import-pixel-pet/references/epbaby-contract.md)。
6. 在生成拼豆图纸前，阅读 [拼豆图纸契约](references/beads-template.md)。

## 要求输入信息完整

必须提供至少一张清晰的角色参考图、所需动作列表及每个动作的简短说明，并明确不得变化的身份特征，例如服装、发型、武器、惯用手和道具。

如果缺少参考图或动作说明，应暂停并向用户索取。不得自行虚构角色或动作列表。为宠物分配稳定的小写短横线格式 ID，并在后续修订中保持不变。

## 阶段一：生成并验收动作精灵图

1. 在生成拼豆图纸前，先把每个所需动作生成为相互独立的精灵序列。
2. 每个动作从 8 帧开始，不同动作可以独立选择帧数。
3. 按最终计划的帧时长渲染动画并检查完整循环；循环动作还必须检查最后一帧到第一帧的衔接。
4. 只有在满足以下全部条件时，当前帧数档位才算通过：角色轮廓、重心、四肢、服装、头发、武器和特效的运动轨迹连续；角色身份、比例、色板、视角、地面线和道具归属保持稳定；关键动作姿势表达清晰；播放时没有可见跳变、停顿、重复帧造成的卡顿或节奏异常。
5. 如果 8 帧未通过，应重新生成有实际动作变化的中间帧并升级到 16 帧；如果 16 帧仍未通过，则升级到 32 帧。禁止通过复制帧或交叉淡化来满足帧数要求。
6. 在 8、16、32 中选择能够通过验收的最小档位，并记录每个动作采用该帧数的原因。
7. 每一帧都必须保留一张透明背景、硬像素边缘的独立图片。可以额外提供精灵图集，但不能用图集替代独立帧文件。

只有全部阶段一动作通过视觉验收后，才能进入阶段二。

## 选择紧凑的统一画布

使用能够保留角色身份和动作表现的最小细节档位：

1. 首先尝试最长边不超过 32 像素的原生紧凑画布。
2. 如果 32 像素无法保留人体结构、面部、服装、道具或动作清晰度，则升级到 64 像素档位。
3. 如果 64 像素仍然会丢失必要细节，则升级到 128 像素档位。
4. 只有在武器、翅膀、载具或特效尺寸确实无法避免时，才允许使用 epBaby 的 192 像素上限，并说明 128 像素不足的原因。

档位表示最长边上限，并不要求输出浪费空间的正方形。应计算所有已批准帧在对齐后的前景联合边界，再裁切为能够容纳该联合边界及最少留白的统一宽度和高度。

整个宠物必须遵守：

- 使用统一画布、比例、枢轴点、水平锚点和地面线；
- 只允许整数像素平移；
- 将联合前景尽量靠近顶部，顶部目标留白为 2 像素；除非上举的武器或特效确有需要，否则顶部留白不得超过画布高度的 5%；
- 联合前景最低像素下方仅保留 1–3 像素；
- 联合前景左右两侧各保留 2–4 像素；
- 根据内容推导实际宽高，禁止把角色放进预设正方形后居中而浪费空间。

禁止为了让单帧局部边界看起来居中而重新移动各帧。固定角色位置优先于单帧局部居中。

## 阶段二：为每一帧生成一张拼豆图纸

必须从阶段一已批准的帧图片确定性生成图纸。禁止使用图像生成模型重新绘制或解释拼豆图纸。

对每一帧执行以下步骤：

1. 创建并清空新的图纸缓冲区。
2. 只加载当前这一帧。除非已经明确并验证每一帧的边界，否则禁止直接裁切多帧图集。
3. 精确保留每一个有色像素和透明单元格。禁止插值、抗锯齿、平滑处理，也不得在网格内部增加装饰。
4. 将颜色映射到固定色板和稳定的拼豆色号，并将索引 `0` 保留为透明色。
5. 遵循 `reference/Beads_demo/` 的结构：坐标网格、较粗的间隔辅助线、有色格内的拼豆色号，以及放置在网格外、包含色号、色块、十六进制颜色值和准确数量的图例。
6. 所有图纸必须保持相同的画布、枢轴点、地面线、比例和角色坐标。
7. 图纸文件命名为 `<pet-id>-<action-id>-chart-NN-of-TT.png`。

图纸数量必须与已批准的精灵帧数量完全一致。如果在检查图纸动画时发现卡顿，应回到阶段一，将该动作从 8 帧升级到 16 帧或从 16 帧升级到 32 帧，重新生成该动作，再重新生成该动作的全部图纸。

## 禁止不同帧相互污染

每张图纸只能包含一个动作帧。每处理一帧，都必须重新创建提取状态和目标缓冲区，并确认没有任何来自相邻帧的组件、道具、特效、阴影或像素混入当前图纸。

每张图纸必须同时满足：

- 图纸中的有色单元格数量等于源精灵帧中的有色像素数量；
- 每一种色号的数量等于源精灵帧的索引色数量；
- 从图纸重建出的结果与源精灵帧具有相同的索引尺寸、色板索引、透明区域和像素坐标；
- 图纸与源精灵帧的逐像素差异必须为零。

任何非零差异或数量不一致都表示失败。必须修复提取逻辑，禁止通过隐藏差异来通过验收。

## 阶段三：只能根据已批准图纸构建宠物

将已批准的拼豆图纸视为最终且唯一的数据源。禁止重新根据角色参考图或阶段一精灵图绘制宠物。

1. 确定性解码每张图纸的网格，得到索引像素数据。
2. 提取时必须排除标题、坐标、网格线、图例、水印和页面上的相邻内容。
3. 精确保留每个有色单元格的坐标和色号，并把每个空单元格保留为透明色。
4. 原样复用图纸的画布、帧顺序、播放时长、枢轴点、锚点和地面线，禁止缩放或插值。
5. 创建 `scripts/generate-<pet-id>.mjs`，禁止覆盖其他宠物的生成器。
6. 使用不超过 256 个条目的色板，并保证索引 `0` 严格等于 `#00000000`。
7. 为每个图层和每一帧创建完整画布长度的 cel。在不改变最终合成结果的前提下，尽可能拆分为稳定的 `body`、`costume`、`face` 和 `prop` 图层。
8. 将最终项目中的每一帧重新渲染为索引像素，并与解码后的图纸比较。每一帧都必须达到零像素差异，并且每个色号的数量完全一致。

“100% 按图纸还原”表示坐标、色号、透明度、尺寸和帧顺序均为零差异。视觉上相似不能视为合格。

## 按顺序执行验证

1. 按最终播放时长检查阶段一的每个动作，并确认其采用的 8、16 或 32 帧档位。
2. 检查每张图纸的角色位置、紧凑留白、裁切和跨帧污染情况。
3. 对每一帧执行精灵图到拼豆图纸的往返验证和逐色号数量检查。
4. 只能根据已批准的拼豆图纸生成项目 JSON。
5. 对每一帧执行拼豆图纸到项目帧的往返验证和逐色号数量检查。
6. 如果所有动作使用相同帧数，运行 `node .agents\skills\import-pixel-pet\scripts\validate-project.mjs default-pets\<pet-id>.json <expected-frames>`。如果不同动作使用不同帧数，则省略可选帧数参数，并在生成器中分别断言每个动作的帧数。
7. 使用 `scripts/render-project-preview.mjs` 渲染最终 JSON，并检查每一帧。
8. 将生成器加入 `pet:generate-default`，并添加一次性默认宠物迁移记录。
9. 运行 `npm.cmd run build`。
10. 验证 `dist/renderer/default-pets/<pet-id>.json` 与源 JSON 完全一致。

如果动作流畅度、帧隔离、画布留白、任一方向的往返验证、项目验证或构建存在失败，不得报告任务完成。

## 交付内容

报告输入参考图和动作列表；精灵帧文件和动画预览；每个动作选择的帧数档位；拼豆图纸目录和图纸数量；画布尺寸、联合边界、枢轴点、地面线和留白；精灵图到图纸以及图纸到项目的零差异结果；项目 JSON、生成器、迁移位置、色板、图层、动作和帧；全部验证与构建结果；以及是否启动过 Electron。
